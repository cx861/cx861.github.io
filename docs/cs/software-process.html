一、基本概念 选择 · 填空 · 名词解释

项目与软件项目

项目P1：在给定的资源条件下，按客户要求，在给定时间期限内，完成特定目标的一次性工作。
资源：完成项目所需要的人力、物力和财力。
客户：提供资金，并确定利益相关方需求的组织或个人。
软件项目P2：在给定的资源条件下，按客户要求，在特定时间、预算内，依据规范，完成特定的软件开发目标的一系列独特的、复杂的、相互关联的活动。
项目管理：以项目为对象，通过使用知识、技能、工具和方法来组织、计划、实施并监控项目，使之满足项目目标需求的过程。
软件过程P3：指软件生存周期所涉及的开发和维护软件及其相关产品（项目计划、设计文档、代码测试用例和用户手册等）的一系列活动，主要包括生产活动和管理活动。
软件过程管理：以软件项目为对象，对软件项目开发过程中所涉及的过程人员、产品、成本和进度等要素进行度量、分析、规划、组织和控制的过程，以确保软件项目按照预计的进度完成。

软件项目管理知识领域

软件项目管理的知识领域P4：
范围管理、时间管理、成本管理、质量管理、人力资源管理、沟通管理、风险管理、采购管理、项目集成管理。
范围管理P7：确保项目只做且必须做完成项目所需的全部工作的过程。
范围管理计划P8：说明项目团队如何确定项目范围，制订详细的项目范围说明书，确定与制作工作分解结构，核实与控制项目范围的规划工具。
WBS（工作分解结构）P13：一种以结果为导向的分析方法，用于分析项目所涉及的工作，所有这些工作构成了项目的整个范围。
范围控制P19：当项目范围发生变化时对其采取纠正措施的过程，以及为使项目向着目标方向发展而对某些因素进行调整所引起的项目范围变化的过程。

进度管理

进度计划P22：进度计划是项目计划的核心部分，依托 WBS 拆解具体活动、理清活动先后关系、估算资源与耗时后编制而成。
活动定义：识别和记录为完成项目可交付成果而需采取的具体行动的过程。
进度控制P31：监督项目活动的状态，更新项目进度，管理进度基准变更，从而实现项目计划的过程。

成本管理

软件项目成本P33：软件项目在整个生命周期中所耗费的全部费用。
成本管理：为了确保项目在批准的预算内完成项目所进行的管理过程。
软件项目规模度量方法：源代码程序长度的测量（LOC）、系统功能数量的测量（FP）。
项目成本控制P42：在项目实施过程中，按照事先确定的项目成本预算基准，通过运用适当的技术和管理手段，对项目实施过程中所消耗的成本使用情况进行管理控制，以确保项目的实际成本限定在预算范围内。
挣值管理法P45：一种综合了范围、进度、成本的项目绩效衡量方法。
计划值（PV）：按计划应该完成工作的预算成本。
实际成本（AC）：实际已经完成工作所花费的实际成本总和。
挣值（EV）：实际已经完成工作的预算价值。

质量与测试

质量P49：反映实体满足明确的和隐含的需求的能力的特性的总和。
质量计划P52：进行项目质量管理，实施项目质量方针，确保达到质量标准的具体规划。
软件评审P57：由开发人员的技术同行在项目实施的各个阶段进行的有组织的软件浏览、文档与代码审计活动，验证工作是否符合预定的标准。
软件测试P59：为了发现错误而执行程序的过程。

绩效与沟通

绩效管理P75：各级管理者为了达到组织目标，在持续沟通的前提下，与员工共同进行绩效计划制订、绩效辅导实施、绩效考核评价、绩效反馈面谈、绩效目标提升的持续循环过程。
沟通管理P78：确保项目信息及时且恰当的生成、收集、分发、存储与最终处置的过程。
干系人：积极参与项目或其利益在项目执行中或成功后受到积极或消极影响的组织和个人。

风险与配置

风险P89：遭受损失、伤害、破坏的可能性，是损失发生的不确定性，是不期望发生事件造成的不利情况。
项目风险管理过程P90：风险识别、风险分析、风险应对、风险监控。
软件维护P99：在软件交付使用后，为改正错误或满足新需求而修改软件的活动。
软件配置管理：在软件整个生命周期中，对软件配置进行管理的活动，建立和维护产品的完整性和一致性。
软件配置：软件在不同时期的版本状态。
软件配置项：项目中可以单独进行配置管理的工作产品。
基线P101：已经通过正式评审和批准的某个规格说明书或产品，可作为进一步开发的基础，并且只能通过正式的变更控制过程被改变。
项目采购管理P116：包括从项目团队之外获取产品或服务的全过程。
项目集成管理P122：利用系统的方法、模型、工具，全面考虑软件项目从启动到结束整个过程中各个参与方之间的动态关系，对项目相关资源进行整合，以达到项目预期目标的管理模式。
项目验收P127：检查项目是否符合合同规定各项要求，对已经完成的工作成果和项目活动进行审核、确认和接收的环节。

二、简答题 完整版 · 原文展开

项目的特点是什么？P1

  • 临时性：每个项目都有确定的开始时间和结束时间，项目团队通常也是临时性的，项目结束团队随之解散。
  • 独特性：项目可交付的成果是独特的，项目产出的产品或服务是独一无二的，不同于批量生产的产品。
  • 渐进性：项目的开发是项目组成员齐心协力、按要求逐步完善的过程，随时间推进不断深入直至完成。

软件项目的制约因素是什么？P2

范围、成本、进度、质量、工作、客户满意度。

软件过程大致包括哪几类？P3

  • 基本过程：构成软件生存周期主要部分的过程，包括获取、供应、开发、操作、维护等过程。
  • 支持过程：为项目开发提供支持的过程，包括文档开发、配置管理、质量保证、验证、确认、联合评审、审计、问题解决等。
  • 组织过程：用于建立、实施基础结构并不断改进的过程，包括基础设施、改进过程、培训过程等。

软件过程的作用是什么？P3

  • 掌握软件开发的基本原则，有助于做出明智的决定。
  • 可标准化软件开发工作，提高软件组织能力成熟度级别以及团队成员合作能力。
  • 可以随时吸收先进的软件开发经验，提高开发效率。
  • 可以精确定义需求变更管理，使变更前后的软件版本之间平滑过渡。
  • 保障了软件过程本身具有可操作性，避免软件过程的不可实施性。

软件过程的特点有哪些？P3

  • 过程描述了所有活动，包含需求分析、设计、编码、测试、交付、维护等全部环节。
  • 过程在一定限制下使用资源，产生中间产品和最终产品。
  • 过程由以某种方式连接的子过程构成，活动以一定顺序组织，过程具有结构性。
  • 每个过程活动都有人口和出口准则，明确活动的开始与结束条件。
  • 每个过程都有达到活动目标的相关指导原则。

软件项目管理的知识领域包括哪些？P4

范围管理、时间管理、成本管理、质量管理、人力资源管理、沟通管理、风险管理、采购管理、项目集成管理。

项目范围管理的主要内容包括哪些？P7

  • 项目起始的确定和控制
  • 项目范围的规划
  • 项目范围的界定
  • 项目范围的确认
  • 项目范围变更的控制与项目范围的全面管理和控制

收集需求的方法有哪些？P10

  • 访谈：最简单直接的需求收集方式，交流深入，适用于各类商务场景。
  • 焦点小组会议：将选定干系人与主题专家集中，了解对产品的期望与态度。
  • 引导式研讨会：邀请跨职能干系人集中讨论，快速定义产品需求。
  • 群体创新技术：组织群体活动识别项目与产品需求。
  • 群体决策技术：评估方案并对需求进行归类与优先级排序。
  • 问卷调查：面向众多受众快速收集信息，效率高、覆盖广。

制定 WBS 的原则 P15~P16

  • 逐层分解原则：按照大项目 → 项目 → 阶段 → 任务 → 工作单元逐级细化。
  • 两周工作包原则：最小级别任务工期控制在 10~14 个工作日，便于管控。
  • 责任到人原则：每个任务仅有一个负责人，便于定位问题与责任。
  • 风险分解原则：风险较大的任务进一步细分，提前暴露与解决风险。
  • 逐步求精原则：近期任务精细分解，远期任务可适当粗放，执行时再细化。
  • 团队工作原则：项目经理与成员共同讨论确认分解结果，达成共识。

分解 WBS 的方法有哪些？P16

  • 按产品的物理结构分解
  • 按产品或项目的功能分解
  • 按照实施过程分解
  • 按照项目的地域分布分解
  • 按照项目的各个目标分解
  • 按部门分解
  • 按职能分解

项目范围变更的控制流程 P20

  • 分析和确定影响项目范围变动的因素与环境条件。
  • 管理和控制那些能够引起项目范围变动的因素与条件。
  • 分析和确认各方面提出的项目变动要求的合理性与可行性。
  • 分析和确认项目范围变动是否已实际发生，以及这些变动的风险和内容。
  • 当项目范围变动发生时，对其进行管理和控制，设法使这些变动朝有益的方向发展，消除不利影响。

项目活动间的逻辑关系有哪些？P24

  • 完成 - 开始（FS）：前一活动完成后，后一活动才能开始，是最常用的关系。
  • 完成 - 完成（FF）：前一活动完成后，后一活动才能完成。
  • 开始 - 开始（SS）：前一活动开始后，后一活动才能开始。
  • 开始 - 完成（SF）：前一活动开始后，后一活动才能完成。

活动历时的估算方法有哪些？P27

  • 专家判断：利用经验丰富人员的专业知识与历史经验进行估算。
  • 类比估算：参考以往类似项目活动的实际持续时间进行估算。
  • 参数估算：用工作数量乘以生产率计算得出活动历时。
  • 三点估算：结合最乐观时间、最可能时间、最悲观时间加权平均计算。

项目进度管理图示有哪些？P29

  • 甘特图：以横道展示活动起止时间，简单直观、易绘制、易理解。
  • 里程碑图：标识项目关键节点与重要事件，明确阶段目标。
  • 网络图：体现活动顺序、依赖关系与逻辑路径。
  • 资源图：反映项目资源分配、使用与负荷情况。

软件项目的成本构成 P33

  • 人力成本
  • 软硬件资源成本
  • 管理成本
  • 培训成本
  • 维护成本
  • 风险储备成本

软件项目成本估算方法有哪些？P35

  • 代码行估算法：以代码行数度量软件规模并估算成本。
  • 功能点估算法：基于系统功能数量进行度量与估算。
  • 类比估算法：参考历史相似项目数据进行估算。
  • 自下而上估算法：从底层工作包汇总得出项目总成本。
  • 参数估算法：利用参数模型与公式计算项目成本。
  • 参数化建模法：采用数学模型进行系统化成本估算。

项目成本估算的作用 P39

  • 对项目资源进行分配，形成时间与资源双重约束。
  • 作为成本控制的标准与衡量依据，及时监控偏差。
  • 可随项目变更动态调整，保障预算适配实际情况。
  • 实现资源系统整体规划，避免小偏差累积成重大问题。

质量管理工作有哪几个层次？P50

  • 质量控制：通过检验筛查缺陷，保障产品符合规格。
  • 质量保证：规范开发流程，保障过程稳定可靠。
  • 质量管理：以预防为主，全过程系统化管理质量。
  • 全面质量管理：全员参与、全生命周期管控，追求卓越质量。

Boehm 模型 P51

Boehm 质量模型为分层结构，从可使用性、可移植性、可维护性三大方面评价软件质量，底层引入量化标准，可综合得出软件质量的总体评估结果。

软件质量与成本之间的关系 P54

软件项目质量越高，故障损失越低；高质量需要投入更高的预防与鉴定费用。总质量成本曲线存在最佳质量点，在该点预防成本与故障损失成本均衡，项目总质量成本最低。

软件测试的分类方法 P59

  • 按测试阶段：单元测试、集成测试、确认测试、系统测试、验收测试。
  • 按测试技术：黑盒测试、白盒测试、灰盒测试。
  • 按质量属性：功能测试、性能测试、兼容测试、可靠性测试等。
  • 按实施主体：α 测试（内部测试）、β 测试（用户试用测试）。

软件质量度量有哪几种指标？P60

  • 缺陷密度：单位规模软件所包含的缺陷数量，反映产品缺陷水平。
  • 平均失效时间（MTTF）：软件两次失效之间正常工作的平均时间，衡量可靠性。
  • 平均修复时间（MTTR）：软件从发生故障到修复完成所需的平均时间，衡量可维护性。
  • 初期故障率：软件交付使用初期（约 1~3 个月）的故障发生频率，反映软件的初始质量水平。
  • 偶然故障率：软件进入稳定期后随机发生的故障频率，衡量软件运行可靠性。

软件人员的特点有哪些？P63

  • 知识型员工：知识水平高、能力强，具有稀缺性与不可替代性。
  • 高主观经验性：经验价值高，对项目影响显著。
  • 高自主性：对工作方式与环境有较高要求。
  • 成就感强：追求卓越，渴望实现自我价值。
  • 主观能动性强：工作效果受个人状态影响大。
  • 效率波动性大：受情绪、环境等因素影响明显。
  • 资源消耗性：需要投入设备、资金、时间等资源。
  • 不可存储性：个人时间、精力、知识无法储存复用。

软件项目团队的组织结构有哪几种？P65

  • 封闭式：层次清晰、秩序规范，适合成熟常规项目。
  • 随机式：组织松散、自由度高，利于技术创新。
  • 开放式：兼顾秩序与创新，协商决策、协作完成。
  • 同步式：分工明确，各自完成模块后集成交付。

团队建设需要经历哪几个阶段？P67

形成阶段、震荡阶段、规范阶段、成熟阶段、重组阶段。

需求层次理论是什么？P73

马斯洛需求层次理论将人的需求从低到高分为五层：生理需求、安全需求、社会需求、尊重需求、自我实现需求。

绩效管理过程 P76

绩效计划制订 → 绩效辅导实施 → 绩效考核评价 → 绩效反馈面谈 → 绩效目标提升。

沟通方式有哪几类？P81

  • 交互式沟通：多方实时互动交流，如会议、电话、视频。
  • 推式沟通：主动发送信息给接收方，如邮件、报告、公告。
  • 拉式沟通：接收方主动获取信息，如内网、知识库、在线文档。

沟通原则有哪些？P82

  • 学会倾听，准确理解对方意图。
  • 表达准确，无歧义、无遗漏。
  • 及时沟通，发现问题快速同步。
  • 双向沟通，确保信息传递与反馈闭环。

沟通障碍有哪些？P86

  • 主观障碍：认知偏差、情绪影响、心理畏惧、地位差异等。
  • 客观障碍：空间距离、层级过多、信息传递失真、文化差异等。
  • 沟通方式障碍：语言不当、方式选错、渠道混乱等。

项目风险管理过程包括哪些内容？P90

风险识别、风险分析、风险应对、风险监控。

风险分析技术主要有哪些？P95

情景分析法、专家决策法、损失期望值法、评分矩阵、模拟仿真法、决策树分析法、敏感性分析法、数学模型或系统模型、风险评审技术、网络仿真系统。

积极风险应对策略有哪些？P96

开拓、分享、提高、接受。

消极风险应对策略有哪些？P96

回避、转移、缓解、接受。

软件配置管理的基本活动有哪些？P102

关键路径计算 P28

最早开始时间 ES、最早完成时间 EF
EF = ES + 活动工期
最晚完成时间 LF、最晚开始时间 LS
LS = LF - 活动工期
总时差 TF
TF = LS - ES

总时差 TF = 0 的活动为关键活动，串联形成的路径为关键路径，决定项目最短工期。

挣值管理计算 P45

成本偏差：CV = EV - AC
进度偏差：SV = EV - PV
成本绩效指数：CPI = EV / AC
进度绩效指数：SPI = EV / PV

判别标准：

  • CV > 0 成本节约，CV < 0 成本超支
  • SV > 0 进度超前，SV < 0 进度滞后
  • CPI > 1 成本效率好，CPI < 1 成本效率差
  • SPI > 1 进度效率好，SPI < 1 进度效率差
