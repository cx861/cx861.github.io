1.2.6 计算机系统的工作原理

一、"存储程序"工作方式

程序执行 = 周而复始的"取指—译码—执行"循环：

根据PC取指令 → 指令译码，PC←PC+1 → 取操作数并执行 → 送结果 → 循环
  • 程序计数器(PC)：存放下一条指令地址
  • 顺序指令：PC ← PC + 指令长度
  • 跳转指令：PC ← 指令中指定的目标地址

第2章 数据的表示和运算

2.1 数制与编码

2.1.1 进位计数制及其相互转换

一、采用二进制的原因 ⭐（2018考点）

  1. 二进制只有两个状态，硬件实现成本低
  2. 二进制编码/计数/运算规则简单，可用逻辑门电路高效实现

二、常用进位计数制

进制基数数码特点
二进制(B)20,1计算机内部使用
八进制(O)80~73位二进制=1位八进制
十进制(D)100~9日常生活
十六进制(H)160~9, A~F4位二进制=1位十六进制

三、进制转换

转换类型方法关键规则
二→八/十六分组替换小数点分界，整数向左/小数向右分组，不足补0
任意进制→十进制按权展开相加各位数码×位权(基数幂次) 之和
十进制→任意进制基数乘除法整数：除基取余（倒序）；小数：乘基取整（正序）

关键结论 ⭐（2021、2022考点）：

  • 并非所有十进制小数都能用有限位二进制精确表示
  • 能被有限位二进制精确表示的十进制小数 ⇔ 可表示为 k/2ⁿ 形式
  • 例如：0.3 = 3/10（10含质因数5），无法精确表示为二进制

2.1.2 定点数的编码表示

一、真值和机器数

  • 真值：带正负号的数值（如+15、-8）
  • 机器数：符号被数字化的表示（0表示正、1表示负）

二、定点表示

  • 定点小数：小数点位于符号位之后、数值最高位之前
  • 定点整数：小数点位于数值最低位之后
  • 机器内部无实际小数点，仅人为约定位置

三、四种编码对比 ⭐⭐⭐

特性原码补码反码移码
正数表示符号0+绝对值与原码相同与原码相同符号1+绝对值
负数表示符号1+绝对值绝对值取反+1绝对值按位取反真值+偏置值
+0/-0有(+0和-0)唯一(全0)有(+0和-0)唯一(1,00..0)
n+1位整数范围-(2ⁿ-1)~2ⁿ-1-2ⁿ~2ⁿ-1-(2ⁿ-1)~2ⁿ-1-2ⁿ~2ⁿ-1
加减法复杂统一为加法复杂—
主要用途浮点尾数现代计算机标准中间过渡(极少用)浮点阶码

补码关键特性 ⭐（2010-2024高频）：

  • [+0]补=[-0]补=0,00...0（全0）
  • [-1]补=1,11...1（全1）
  • 最大正整数：[2ⁿ-1]补=0,11...1
  • 最小负整数：[-2ⁿ]补=1,00...0
  • 补码比原码多表示一个最小负数(-2ⁿ)

补码与真值转换（2020、2023考点）：

  • 真值→补码(负数)：符号位取1，其余位"按位取反，末位加1"
  • 补码→真值(负数)：同上法，符号位不变

变形补码（双符号位）：

  • 00表示正，11表示负
  • 左符为真正符号位，右符用于判断溢出

移码特点（用于IEEE 754浮点阶码）：

  • [x]移 = 2ⁿ + x（偏置值通常取2ⁿ）
  • 移码全0→真值最小；移码全1→真值最大
  • 保持真值大小顺序：移码越大，真值越大
  • 补码↔移码：仅符号位相反

四种编码比较大小 ⭐（2015考点）：

  • 正数：原码=反码=补码，直接比较数值位
  • 负数补码/反码比较：数值部分越小，绝对值越大（负得越多）

类型表示范围（n位）特点

二、补码减法

[x-y]补 = [x]补 + [-y]补

其中[-y]补 = 将[y]补连同符号位一起取反，末位加1

判断方法判断条件

2.2.3 定点乘除运算补充

运算核心思想常考关注点
原码一位乘法符号单独处理，数值部分按乘数最低位决定是否加被乘数，再右移部分积、右移次数、符号位确定
补码一位乘法符号位参与运算，常见 Booth 思想根据相邻两位差值决定加/减被乘数末两位判断、算术右移、补码符号扩展
原码除法符号单独处理，数值部分用恢复余数法或不恢复余数法余数符号、商位确定、最后修正
补码除法被除数、除数用补码参与运算，商符与余数符号按规则修正商符、余数符号、溢出判断

易错提醒：逻辑右移高位补0，算术右移高位补符号位；补码乘除中的右移通常是算术右移。

2.3.2 浮点数的加减运算

步骤：

  1. 对阶：小阶向大阶看齐，尾数右移
  2. 尾数求和：按定点加减法运算
  3. 规格化：左规（尾数左移）或右规（尾数右移）
  4. 舍入处理：0舍1入、恒置1等
  5. 溢出判断：阶码是否上溢/下溢

常见舍入方法：

方法规则
0舍1入多余位最高位为1则进1

3.3 主存与Cache的映射 ⭐⭐⭐

3.3.1 Cache的基本工作原理

一、Cache命中过程

  • CPU给出主存地址 → 判断数据是否在Cache中
  • 命中(Hit)：直接从Cache读取
  • 缺失(Miss)：从主存读取块并加载到Cache

二、Cache性能指标

指标定义公式
命中率HCPU访存命中Cache的概率H = 命中次数/总访问次数
平均访问时间Tₐ考虑命中和缺失的平均时间Tₐ = H×T꜀ + (1-H)×Tₘ
Cache-主存系统效率—e = T꜀/Tₐ

更常用的缺失代价写法：

平均访问时间 AMAT = 命中时间 + 缺失率 × 缺失代价
缺失率 = 1 - 命中率

Cache表项常见控制位：有效位 valid 判断该行内容是否有效；脏位 dirty 用于写回法，表示该块被修改且尚未写回主存。

3.3.2 Cache地址映射方式 ⭐⭐⭐

一、三种映射方式对比

特性直接映射全相联映射组相联映射
映射规则主存块只能映射到固定Cache行主存块可映射到任意Cache行主存块可映射到固定组内任意行
主存地址划分标记+行号+块内地址标记+块内地址标记+组号+块内地址
比较电路简单（1路比较）复杂（全路同时比较）折中（组内全相联比较）
命中率较低（冲突多）最高较高
实现复杂度最简单最复杂适中
典型应用大容量Cache小容量TLB当前主流Cache

二、地址映射计算

直接映射：

Cache行号 = (主存块号) mod (Cache总行数)
主存地址 = {标记(tag), Cache行号(index), 块内地址(offset)}

组相联映射（n路组相联）：

Cache组号 = (主存块号) mod (Cache组数)
每组有 n 行（即n路），组内全相联

3.3.3 Cache替换算法

算法规则实现难度命中率
随机算法(RAND)随机选择替换块最简单较低
先进先出(FIFO)替换最早装入的块较简单较低
近期最少使用(LRU)替换最久未使用的块较复杂（需计数）较高
最不经常使用(LFU)替换访问次数最少的块复杂较高
随机+LRU近似如时钟算法等折中较好

3.3.4 Cache写策略 ⭐

一、写命中策略

策略操作优点缺点
写直达(Write Through)同时写入Cache和主存数据一致性好，简单写操作慢，总线流量大
写回(Write Back)仅写入Cache，替换时写回主存写操作快，总线流量小数据一致性问题，需脏位

二、写缺失策略（写不命中）

策略操作说明

3.4 虚拟存储器 ⭐⭐

3.4.1 虚拟存储器的基本概念

  • 虚拟存储器：将主存和辅存统一编址，形成逻辑上统一的地址空间
  • 虚拟地址(逻辑地址) → 物理地址 的转换
  • 页/段是虚拟存储器的基本单位

3.4.2 页式虚拟存储器

一、基本概念

概念说明
页(Page)虚拟地址空间等分成的固定大小块
页框(Page Frame)主存空间等分成的与页大小相同的块
页表记录虚拟页→物理页框映射关系的表
页表项包含物理页框号、有效位、访问位、脏位等

二、地址转换：

虚拟地址 = {虚页号, 页内偏移}
物理地址 = {物理页框号, 页内偏移}

三、快表(TLB) ⭐（2016-2021高频考点）

概念说明
TLB(快表)页表项的Cache，由高速SRAM实现
慢表(Page)主存中的完整页表
TLB工作原理与Cache类似，采用全相联或组相联映射
TLB表项虚页号(tag) + 物理页框号 + 控制位(有效位、脏位等)

CPU访存的三种缺失 ⭐（2010考点）：

缺失类型说明关系
TLB缺失虚页号不在TLB中—
Cache缺失主存块不在Cache中—
Page缺失(缺页)页面不在主存中缺页→TLB必缺失，Cache也必缺失

TLB + Cache 访问顺序：

  1. CPU产生虚拟地址，先用虚页号查TLB。
  2. TLB命中则得到物理页框号；TLB缺失但页面在主存，则查页表并回填TLB。
  3. 若页表项无效，产生缺页异常，由操作系统调页。
  4. 得到物理地址后，再访问Cache或主存。

3.4.3 段式虚拟存储器

  • 按程序的逻辑结构（代码段、数据段等）划分
  • 段表记录：段号→段基址、段长、访问权限等
  • 优点：便于共享和保护
  • 缺点：段长不等，内存碎片问题

3.4.4 段页式虚拟存储器

  • 结合段式和页式：程序按逻辑分段，每段再分页
  • 地址转换：段号→段表→页表起始地址→页号→物理地址
  • 兼具段式的逻辑清晰和页式的内存利用高效

5.2.1 指令执行的一般流程

  3. 取操作数(OF)：根据寻址方式获取操作数
  4. 执行(EX)：ALU运算或访存操作
  5. 写回(WB)：结果写入寄存器或存储器

PC更新规则：

  • 顺序执行：PC ← PC + 指令长度
  • 转移指令：PC ← 转移目标地址

  • 双总线结构：两条内部总线，可并行传输
  • 三总线结构：三条内部总线，速度最快但成本最高

一、结构冒险（资源冲突）

解决方法：

  • 指令Cache和数据Cache分离（哈佛结构）
  • 增加硬件资源（如增加ALU数量）

二、数据冒险（数据相关） ⭐⭐⭐

后续指令需要使用前面指令的结果，但结果尚未产生。

类型说明解决方式
RAW(写后读)前条写，后条读同一寄存器转发/旁路(Forwarding)
WAR(读后写)前条读，后条写同一寄存器寄存器重命名
WAW(写后写)前后条写同一寄存器寄存器重命名

数据冒险解决方法：

  1. 转发/旁路(Forwarding/Bypassing)：将ALU结果直接前递到后续指令的输入端
  2. 阻塞/停顿(Stall/Bubble)：插入气泡（NOP）等待数据就绪
  3. 编译器调度：重排指令顺序避免冲突

三、控制冒险（控制相关）

转移指令导致流水线中后续指令的PC值不确定。

解决方法：

  1. 阻塞：等待转移结果确定
  2. 静态分支预测：编译时确定预测方向
  3. 动态分支预测：运行时根据历史信息预测（如BTB、BHT）
  4. 延迟分支：在转移指令后安排一条必定执行的指令

一、单位与口径检查

  • 题目写“按字节编址”时，一个地址对应 $1$ B；字长不自动改变地址单位。$1$ B $=8$ bit，存储容量的 KiB 按 $2^{10}$ B 计算。
  • CPU 时间 $=\text{指令条数}\times\text{平均 CPI}/\text{时钟频率}$，不能只比较主频。
  • 计算 Cache 行数用数据区容量除以块大小；若题目给总容量，可能还包含标记、有效位、脏位及替换信息。

二、自编例题：组相联 Cache 地址划分

条件：32 位字节地址，Cache 数据区 32 KiB，块大小 64 B，4 路组相联。

  1. Cache 行数 $=32768/64=512$，组数 $=512/4=128$。
  2. 块内偏移 $\log_2 64=6$ 位，组号 $\log_2 128=7$ 位。
  3. 标记 $=32-6-7=19$ 位，地址从高到低为“标记 19 | 组号 7 | 偏移 6”。
  4. 地址 0x00002040 的块号为 $129$，组号 $129\bmod128=1$，标记 $\lfloor129/128\rfloor=1$，偏移为 $0$。

扩展：只计标记和有效位时，每行额外 $20$ bit，共 $10240$ bit（1280 B）；写回 Cache 还要另计脏位，替换信息按题设计算。

三、自编例题：平均访存时间

命中时间 2 ns，命中率 95%，缺失惩罚为命中检测之后额外增加的 80 ns，则 AMAT $=2+0.05\times80=6$ ns。若题目把“缺失总耗时”定义为 80 ns，则应为 $0.95\times2+0.05\times80=5.9$ ns；先读清时间是否包含命中检测。

四、自编例题：补码溢出

8 位补码中，$100+60=160$ 超出 $[-128,127]$。位运算结果是 10100000，解释成有符号数为 $-96$，故发生溢出。该加法没有最高位向外的进位，说明“进位”和“有符号溢出”不是一回事。同号相加结果异号，是补码加法溢出的常用判据。

1. 性能指标与局部加速

先记条件：CPU 时间=指令数×平均 CPI/频率；加速比以原系统耗时占比加权，不能直接平均各部分加速倍数。

计算机组成原理 01｜程序执行 10⁹ 条指令，三类占比 0.5、0.3、0.2，CPI 分别 1、2、4，主频 2 GHz。求运行时间。

展开推演、易错点与检查
  1. 平均 CPI=0.5×1+0.3×2+0.2×4=1.9，总周期数 1.9×10⁹。
  2. 频率 2×10⁹ 周期/秒，时间为 0.95 秒；这是题设固定指令数与 CPI 下的 CPU 时间。

易错原因：把 CPI 做不加权的算术平均；混淆 GHz 与纳秒。

检查动作：单周期时长 0.5 ns，乘总周期仍得到 0.95 s。

计算机组成原理 02｜原耗时中 60% 的部分加速为原来的 3 倍，其余不变。总体加速比是多少？

展开推演、易错点与检查
  1. 将原时间归一为 1，新时间为 0.4+0.6/3=0.6。
  2. 总体加速比 1/0.6=5/3≈1.667；即使该部分无限快，极限也只有 1/0.4=2.5。

易错原因：计算 0.4×1+0.6×3=2.2，把性能倍数直接加权。

检查动作：先算新耗时再倒数；结果不能超过无限加速上界 2.5。

闭卷自测与答案

问：只提高主频是否必然按同比例缩短程序时间？答：只有指令数和 CPI 等保持不变时才有此结论。

2. 补码运算、移位与溢出

先记条件：先确认位宽和解释方式；有符号溢出与无符号进位是不同标志；算术右移复制符号位。

计算机组成原理 03｜−45 用 8 位补码表示，再分别算术右移、逻辑右移 2 位，结果是多少？

展开推演、易错点与检查
  1. 45=00101101，取反加一得到 −45=11010011。
  2. 算术右移补 1，得 11110100，按补码解释为 −12；逻辑右移补 0，得 00110100=52。
  3. 负数算术右移在此相当于向负无穷取整，−45/4=−11.25，不能写成向零取整的 −11。

易错原因：默认所有右移都补 0；默认算术右移与语言中的有符号除法舍入完全相同。

检查动作：对负结果再次取反加一，应得到绝对值 12。

计算机组成原理 04｜8 位补码计算 −100+(−60)。写出低 8 位结果并判断有符号溢出和无符号进位。

展开推演、易错点与检查
  1. −100 为 10011100，−60 为 11000100；相加得到 1 01100000，低 8 位为 01100000=96。
  2. 真实和 −160 超出 [−128,127]，两负数相加得正数，有符号溢出。
  3. 若将同一位串解释为无符号数，156+196=352=256+96，最高位进位为 1。

易错原因：把截断后的 96 当作正确有符号和；仅凭进位判断有符号溢出。

检查动作：同时用数值范围和同号相加异号结果两种方法判溢出。

闭卷自测与答案

问：127+1 的 8 位运算能否没有最高位进位但有符号溢出？答：能，结果 10000000，进位 0，但正数相加得到负数。

3. IEEE 754 与舍入边界

先记条件：单精度正常数为符号位、8 位阶码和 23 位小数；阶码全 0/全 1 有特殊含义。舍入题必须给出有效位数和规则。

计算机组成原理 05｜把 5.75 写成 IEEE 754 binary32 位字段及十六进制编码。

展开推演、易错点与检查
  1. 5.75=101.11₂=1.0111₂×2²，符号位 0，偏置阶码 2+127=129=10000001₂。
  2. 小数字段为 0111 后补 19 个 0；拼接得到 0x40B80000。
  3. 正常数隐含首位 1；非规格化数阶码全 0、隐含首位 0，binary32 最小正非规格化数为 2⁻¹⁴⁹。

易错原因：把 101.11 的整数部分原样塞进小数字段，或将偏置 127 写成 128。

检查动作：还原为 1.4375×4=5.75；字段位数总和应为 32。

计算机组成原理 06｜玩具二进制格式仅保留 4 位有效数字（含隐含首位），采用最近偶数舍入。1.0625 和 1.1875 各舍入到多少？

展开推演、易错点与检查
  1. 在 [1,2) 区间相邻可表示数间距为 2⁻³=0.125。1.0625 位于 1.000₂ 与 1.001₂ 正中。
  2. 选最低保留位为偶数的 1.000₂，即 1.0；1.1875 位于 1.001₂ 与 1.010₂ 正中，选 1.010₂，即 1.25。

易错原因：遇到二分之一一律进位；没有检查保留结果的最低有效位。

检查动作：先列左右相邻可表示数，再检查两边距离相等时谁的最低位为 0。

闭卷自测与答案

问：阶码全 1、小数全 0 与小数非 0 分别表示什么？答：前者为带符号无穷大，后者为 NaN；不能作为普通偏置阶码计算。

4. Cache 地址划分与冲突

先记条件：按字节编址，数据容量不含标记开销；组数=容量/(块大小×路数)。比较地址时要先去掉块内偏移。

计算机组成原理 07｜32 位字节地址，Cache 数据容量 16 KiB，块 64 B，4 路组相联。求各字段位数。

展开推演、易错点与检查
  1. Cache 共 16384/64=256 行，4 路故有 64 组。
  2. 块内偏移 log₂64=6 位；组号 log₂64=6 位；标记 32−6−6=20 位。

易错原因：用总行数 256 作为组数，导致标记少算 2 位；混淆 KiB 与 KB。

检查动作：20+6+6=32；64 组×4 路×64 B=16 KiB。

计算机组成原理 08｜Cache 共 4 行、块 16 B，初始空。访问字节地址 0、16、64、0、16，比较直接映射与 2 路组相联的命中序列。

展开推演、易错点与检查
  1. 块号依次为 0、1、4、0、1。直接映射取块号 mod 4：0 与 4 竞争行 0，结果为 未中、未中、未中、未中、命中。
  2. 2 路共 2 组，块 0、4 都在组 0 的两路内，块 1 在组 1；序列为 未中、未中、未中、命中、命中。
  3. 本序列各组不会溢出，不依赖替换策略。相同总容量仍可能有不同冲突次数。

易错原因：直接拿字节地址模组数，没有先除块大小；把所有未中都归因于容量不足。

检查动作：逐次画组内块号，命中时不能误替换其他行。

闭卷自测与答案

问：块内不同字节是否必须重新装入 Cache？答：同一块已在 Cache 且有效时无需重新装块，偏移只用于选字节。

5. 多级 AMAT 与未中代价口径

先记条件：明确局部未中率、全局未中率；题给未中代价是额外罚时还是含本次访问总时长，公式不同。

计算机组成原理 09｜L1 每次耗时 1 ns，命中率 95%；L1 未中后额外查 L2 耗时 8 ns，L2 条件命中率 80%；L2 未中再额外访问主存 80 ns。求 AMAT。

展开推演、易错点与检查
  1. L1 局部未中率 0.05；主存访问概率=0.05×0.2=0.01。
  2. AMAT=1+0.05×(8+0.2×80)=2.2 ns。L2 查询时间只由 L1 未中访问承担。

易错原因：把 L2 的 20% 直接当作所有访存的主存概率，或把 L2 命中率解释为全局命中率。

检查动作：分别按概率算 1+0.05×8+0.01×80，结果也为 2.2。

计算机组成原理 10｜命中耗时 3 ns、命中率 90%。若未中额外罚时为 40 ns，AMAT 为多少？若未中分支总耗时为 40 ns 呢？

展开推演、易错点与检查
  1. 额外罚时口径：每次先耗时 3 ns，再以 0.1 概率追加 40，故 3+0.1×40=7 ns。
  2. 总耗时口径：命中分支 3、未中分支 40，故 0.9×3+0.1×40=6.7 ns。

易错原因：对同一个 40 ns 不辨语义直接套固定公式，造成重复计算命中耗时。

检查动作：把两种事件树分别画出；未中分支在第一种模型中实际为 43 ns。

闭卷自测与答案

问：L1 未中率 5%、L2 局部未中率 20%，全局未中率多少？答：1%，前提是 L2 只处理 L1 未中访问。

6. 指令寻址与相对转移

先记条件：先明确 PC 的基准时刻、位移单位、符号扩展和有效地址含义；有效地址不等于最终操作数。

计算机组成原理 11｜指令地址 0x100、长度 4 B，分支相对基准为下一条指令地址，带符号位移为 −3 个字，每字 4 B。求目标地址。

展开推演、易错点与检查
  1. 顺序下一条 PC=0x104；字位移 −3 转为字节位移 −12。
  2. 目标=0x104−0xC=0xF8。先符号扩展再按单位缩放。

易错原因：以当前 0x100 为基准，或把 −3 直接作为 −3 字节相加。

检查动作：反算 0xF8−0x104=−12，除 4 恰为 −3。

计算机组成原理 12｜R1=0x200，位移 0x10，M[0x210]=0x300，M[0x300]=7。基址寻址取数与以 0x210 为指针的存储器间接寻址各读得什么？不计取指。

展开推演、易错点与检查
  1. 基址寻址 EA=R1+0x10=0x210，一次数据访存取到 0x300。
  2. 存储器间接寻址先在 0x210 读取指针 0x300，再在该地址取数 7，共两次数据访存。

易错原因：看到内存里仍是一个地址就自动继续解引用；未按指令寻址方式控制访存次数。

检查动作：把每一次 M[...] 单独画成箭头，区分寄存器数值、地址、内存内容。

闭卷自测与答案

问：立即寻址是否需要一次额外数据访存取操作数？答：立即数在指令中，通常不需要另一次数据访存；取指仍存在。

7. 流水线时序与数据相关

先记条件：理想 k 段等长流水线执行 n 条指令需 k+n−1 个周期；实际必须检查结构、数据、控制相关及转发路径。

计算机组成原理 13｜5 段理想流水线，每段 2 ns，连续执行 20 条独立指令。求耗时与相对非流水执行加速比。

展开推演、易错点与检查
  1. 流水线周期 2 ns，周期数 5+20−1=24，耗时 48 ns。
  2. 非流水按每条 5×2=10 ns 计，共 200 ns；加速比 200/48=25/6≈4.167。

易错原因：忽略灌入与排空，直接写 5 倍；或把周期数写成 20×5。

检查动作：n=1 时应为 10 ns，n 很大时加速比才趋近 5。

计算机组成原理 14｜IF/ID/EX/MEM/WB 五段，具备完整转发、寄存器可同周期先写后读，仅 load-use 需停 1 周期。执行 LW R1,0(R2)；ADD R3,R1,R4；SUB R5,R3,R6，需几周期？

展开推演、易错点与检查
  1. LW：IF1、ID2、EX3、MEM4、WB5。ADD：IF2、ID3，周期 4 停顿，EX5、MEM6、WB7。
  2. SUB：IF3，周期 4 被保持，ID5、EX6、MEM7、WB8；ADD 的结果可转发给 SUB。
  3. 共 8 周期，即理想 5+3−1=7，再加 1 个 load-use 气泡。

易错原因：把 ADD→SUB 的相关也算一次停顿，或认为转发能让尚未从 MEM 读出的 load 数据提前可用。

检查动作：在时序表中标出数据产生阶段与消费阶段，检查是否真的有转发路径。

闭卷自测与答案

问：遇分支是否固定停 2 周期？答：不能脱离模型决定，取决于判定阶段、预测策略和失败恢复代价。

8. 总线带宽与突发传输

先记条件：峰值带宽=每次数据量×每秒传输次数；固定启动开销和有效载荷时间分开计算，MB 与 MiB 不混用。

计算机组成原理 15｜总线宽 64 bit、时钟 100 MHz，每周期传一次。峰值多少 MB/s？若每周期两次呢？

展开推演、易错点与检查
  1. 每次 64/8=8 B；100×10⁶ 次/s，峰值 800×10⁶ B/s=800 MB/s（十进制）。
  2. 每周期两次时为 1600 MB/s；若要 MiB/s，应再除 2²⁰。

易错原因：把位直接当字节，或把时钟频率默认等同于双倍数据传输率。

检查动作：用单位链 bit/次÷8×次/s，约掉中间单位。

计算机组成原理 16｜一次突发传 256 B，数据速率 8 GB/s，另有不能重叠的固定开销 20 ns。求总时间和有效带宽。

展开推演、易错点与检查
  1. 8 GB/s=8 B/ns，载荷传输需 256/8=32 ns；总时间 32+20=52 ns。
  2. 有效带宽 256/52≈4.923 B/ns=4.923 GB/s，小于峰值 8 GB/s。

易错原因：把不能重叠的启动时间遗漏；或把峰值当作含控制开销的有效速率。

检查动作：增大突发长度时固定开销占比应降低，有效带宽趋向峰值。

闭卷自测与答案

问：启动开销与传输可完全重叠时还能直接相加吗？答：不能，应依据重叠时序计算，本题明确禁止重叠。

9. 中断与 DMA 的 CPU 开销

先记条件：区分 CPU 忙于 I/O 的时间与设备实际传输总时长；DMA 仍有设置、完成通知及可能的总线争用。

计算机组成原理 17｜设备每秒 1 MiB 数据，每字节中断一次，每次占用 500 CPU 周期，CPU 1 GHz。只算中断处理，CPU 占比多少？

展开推演、易错点与检查
  1. 1 MiB=1,048,576 B，因此每秒 1,048,576 次中断，耗费 524,288,000 周期。
  2. CPU 每秒 10⁹ 周期，占比 0.524288=52.4288%。

易错原因：用 10⁶ 代替 2²⁰，或忘记频率单位；每字节一次中断是本题设定，不是设备普遍实现。

检查动作：算出单次服务 500 ns，再乘每秒次数应得到约 0.5243 秒。

计算机组成原理 18｜DMA 设备速率 8 MiB/s，每块 4 KiB；CPU 1 GHz，每块设置 200 周期、完成处理 300 周期。求每秒块数及 CPU 开销比例。

展开推演、易错点与检查
  1. 每秒块数 (8×2²⁰)/(4×2¹⁰)=2048。
  2. 每块共 500 周期，一秒占用 1,024,000 周期，即 0.1024%。
  3. 这个数仅计题设两项；设备传输可与 CPU 执行重叠，但访存总线争用还可能影响性能。

易错原因：认为 DMA 完全不占 CPU，或按每字节而非每块累计设置开销。

检查动作：用 2048 块×4096 B 还原速率，确认计算粒度一致。

闭卷自测与答案

问：DMA 总传输历时能否直接等同于 CPU 被占用的时间？答：不能，二者可以重叠，CPU 服务开销应另算。

10. 存储芯片扩展与交叉编址

先记条件：位扩展增加字长，字扩展增加地址深度；交叉存储的并行收益受模块周期和发起间隔共同限制。

计算机组成原理 19｜用 8K×8 芯片组成按字编址的 32K×16 存储器。需几片？模块地址与片内地址各几位？

展开推演、易错点与检查
  1. 字长扩展 16/8=2 片并联；深度扩展 32K/8K=4 组；共 8 片。
  2. 模块有 32K 个字，字地址共 15 位；片内 8K 对应 13 位，其余 2 位选择 4 个组。

易错原因：把按字编址误当按字节编址而多加一位；宽度与深度相加而非相乘。

检查动作：8 片×8K×8 bit 应等于 32K×16 bit。

计算机组成原理 20｜4 体低位交叉，bank=字地址 mod 4。每体占用周期 40 ns，发起时隙间隔 10 ns，发起后恰 40 ns 返回且包含输出时间。求读 0,1,2,3 与读 0,4,8,12 四字的完成时间。

展开推演、易错点与检查
  1. 连续字落在不同体，可于 0、10、20、30 ns 发起，40、50、60、70 ns 返回，最后一字于 70 ns 完成。
  2. 间隔 4 的字全在同一体，只能于 0、40、80、120 ns 发起，最后于 160 ns 返回。
  3. 本题不再追加总线输出时延；若题设另外给出，则必须另画时序。

易错原因：只看到四体就默认四倍速度；不检查地址映射和同体恢复时间。

检查动作：列出每个字的 bank、发起时刻、返回时刻；同一体相邻发起间隔至少 40 ns。

闭卷自测与答案

问：低位交叉一定优于高位交叉吗？答：不能脱离访问模式判断；连续访问有利于低位交叉，同余跨步会集中到同一体。
