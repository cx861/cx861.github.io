一、操作系统基本概念辨析题

题型特征

  • 选择题：判断操作系统特征、功能、接口类型
  • 辨析并发与并行、分时与实时、宏内核与微内核

核心辨析

易混概念核心区分
并发 vs 并行并发=交替(单核也可)，并行=同时(需多核)
内核态 vs 用户态特权指令只能在内核态执行；用户态→内核态通过中断/异常/系统调用
中断 vs 异常中断=外中断(与当前指令无关)；异常=内中断(与当前指令有关)
系统调用 vs 库函数系统调用需陷入内核；库函数可能不涉及系统调用(如strlen)
宏内核 vs 微内核宏：性能高、可靠性差；微：可靠性高、性能较低

典型真题

1. 以下关于操作系统特征的描述，正确的是？

A. 并发和并行是同一个概念
B. 共享性指系统中所有资源可被多个进程同时访问
C. 虚拟性指通过技术将一个物理实体变为多个逻辑对应物 ✅
D. 异步性是可消除的

2. CPU从用户态切换到内核态的途径不包括？

途径包括：系统调用、中断、异常。不包括"修改PSW"（那是内核态→用户态的方式）

涉及知识点：1.1 操作系统的基本概念、1.3 操作系统的运行环境

二、进程状态转换与PCB题

题型特征

  • 给出进程当前状态和事件，判断下一状态
  • PCB包含哪些信息
  • 进程切换的步骤

状态转换判定口诀

运行→阻塞：主动等事件（I/O请求、wait信号）
运行→就绪：被动被抢占（时间片完、被高优先级抢占）
阻塞→就绪：等待的事件发生（I/O完成、信号到达）
⚠️ 不存在：运行→阻塞、就绪→阻塞、阻塞→运行 的直接转换！

典型真题

1. 某进程正在CPU上运行，当发生以下事件时，进程状态如何变化？

(1) 时间片用完 → 运行→就绪
(2) 执行I/O请求 → 运行→阻塞
(3) I/O完成 → 阻塞→就绪
(4) 更高优先级进程到达 → 运行→就绪

2. PCB中不包含的信息是？

PCB包含：PID、状态、优先级、PC值、寄存器、内存指针、打开文件列表等
不包含：进程的完整地址空间内容（那是程序和数据段）

涉及知识点：2.1.2 进程的状态与转换、2.1.3 进程的组织与控制

三、调度算法计算题 ⭐⭐⭐

题型特征

  • 给出多个作业的到达时间和运行时间，计算平均周转时间/等待时间
  • 画出甘特图
  • 比较不同算法的性能

六大算法要点速查

算法策略抢占饥饿风险
FCFS按到达顺序❌无
SJF/SPF选最短的❌/✅ (SRTF)长作业
HRRN响应比=(等待+运行)/运行❌无
RR时间片轮转✅无
优先级选最高优先级可选低优先级
MFQ多队列+反馈✅低优先级(需老化)

计算公式

周转时间 = 完成时间 - 到达时间
带权周转时间 = 周转时间 / 运行时间
等待时间 = 周转时间 - 运行时间
响应时间 = 首次被调度时间 - 到达时间

解题步骤

  1. 列出所有作业的到达时间、运行时间
  2. 按算法规则画出甘特图（时间线+CPU占用）
  3. 计算每作业的完成时间
  4. 代入公式求各指标平均值

典型真题

1. 四个作业：P1(0,8), P2(1,4), P3(2,9), P4(3,5)。分别用FCFS和SJF(非抢占)求平均周转时间。


FCFS：P1[0-8], P2[8-12], P3[12-21], P4[21-26]
周转：P1=8, P2=11, P3=19, P4=23 → 平均15.25

SJF：P1[0-8], P2[8-12], P4[12-17], P3[17-26]
周转：P1=8, P2=11, P4=14, P3=24 → 平均14.25

2. HRRN调度：P1已等8，运行4；P2已等3，运行1。选哪个？

R1 = (8+4)/4 = 3.0；R2 = (3+1)/1 = 4.0 → 选P2

3. RR时间片q=4：P1(0,10), P2(0,4), P3(0,6)。求平均等待时间。

[0-4]P1, [4-8]P2(完成), [8-12]P3, [12-16]P1, [16-18]P3(完成), [18-20]P1(完成)
等待：P1=(4-0)+(12-8)+(18-16)=10, P2=4-0=4, P3=(8-0)+(16-12)=12
平均=8.67

涉及知识点：2.2 CPU调度（调度算法）

四、PV操作与同步互斥编程题 ⭐⭐⭐

题型特征

  • 补全PV操作代码，确保同步互斥
  • 分析给定代码是否会产生死锁
  • 设计信号量解决经典同步问题

核心规则

P操作的顺序规则：先P资源信号量，再P互斥信号量
V操作的顺序规则：先V互斥信号量，再V资源信号量

P/V必须成对出现！
互斥信号量的P和V在同一进程中
同步信号量的P和V在不同进程中（成对但不一定在同一函数）

信号量初始化原则

信号量类型初值含义
互斥信号量 mutex1最多一个进程进入临界区
资源信号量 emptyn可用空位数
资源信号量 full0已填充数

解题步骤

  1. 确定需要几个信号量（互斥的 + 同步的）
  2. 确定每个信号量的含义和初值
  3. 分析每个进程/线程需要等待什么（P）、完成后需要通知什么（V）
  4. 写出完整代码，检查P操作顺序是否会导致死锁

典型真题

1. 生产者-消费者（多生产者、单缓冲区），补全代码标注P/V操作的正确位置。

信号量：mutex=1, empty=n, full=0
Producer: produce → P(empty) → P(mutex) → add → V(mutex) → V(full)
Consumer: P(full) → P(mutex) → take → V(mutex) → V(empty) → consume

2. 下列PV操作是否正确？若有问题，指出问题。

// 错误示例：
Producer: P(mutex); P(empty); ...; V(mutex); V(full);
// 问题：先P(mutex)再P(empty)，若缓冲区满，生产者被阻塞但仍持有mutex
// 导致消费者无法P(mutex)进入→死锁！

3. 三个进程P1, P2, P3协作，要求：P1先执行，然后P2和P3可并发，都执行完后P1继续。

semaphore s2=0, s3=0, done2=0, done3=0;
P1: ...; V(s2); V(s3); P(done2); P(done3); continue...
P2: P(s2); ...; V(done2);
P3: P(s3); ...; V(done3);

涉及知识点：2.3 同步与互斥

五、银行家算法计算题 ⭐⭐⭐

题型特征

  • 判断系统是否处于安全状态
  • 判断某进程的资源请求是否能被满足

安全性算法步骤

1. Work = Available; Finish = [F,F,F,F]
2. 找满足 Finish[i]==F 且 Need[i] ≤ Work 的进程Pi
3. 若找到：Work += Allocation[i]; Finish[i] = T; 返回步骤2
4. 若所有Finish==T → 安全；否则→不安全

解题步骤

  1. 列出Available、各进程的Max、Allocation、Need
  2. 执行安全性算法，记录安全序列
  3. 对于资源请求，先试探分配，再执行安全性检查

典型真题

1. 系统当前可用资源Available=(3,3,2)。进程信息如下，判断是否安全。

进程Max(A,B,C)AllocationNeed
P0(7,5,3)(0,1,0)(7,4,3)
P1(3,2,2)(2,0,0)(1,2,2)
P2(9,0,2)(3,0,2)(6,0,0)
P3(2,2,2)(2,1,1)(0,1,1)
P4(4,3,3)(0,0,2)(4,3,1)
安全序列可为：P1 → P3 → P4 → P0 → P2。
Work变化：(3,3,2)→(5,3,2)→(7,4,3)→(7,4,5)→(7,5,5)→(10,5,7)，所以系统安全。

2. P1请求资源(1,0,2)，能否分配？

检查Request ≤ Need[P1]? (1,0,2) ≤ (1,2,2)? ✓
检查Request ≤ Available? (1,0,2) ≤ (3,3,2)? ✓
试探分配后执行安全性检查...得出安全序列则批准

涉及知识点：2.4.2 死锁避免（银行家算法）

补充：线程模型与死锁检测题 ⭐⭐

题型特征

  • 比较用户级线程、内核级线程、多对一/一对一/多对多模型
  • 判断线程阻塞是否会导致整个进程阻塞
  • 给定资源分配矩阵，判断是否存在死锁

线程模型速查

模型优点缺点
用户级线程切换快，不需进入内核一个线程阻塞可能导致整个进程阻塞
内核级线程可多核并行，一个线程阻塞不影响其他线程创建、撤销、切换开销较大
多对一用户态管理，效率高不能真正并行
一对一并发性好内核线程数量多，开销大
多对多折中，灵活实现复杂

死锁检测算法

Work = Available
Finish[i] = (Allocation[i] == 0)
寻找 Request[i] <= Work 且 Finish[i] == false 的进程Pi
若找到：Work += Allocation[i], Finish[i] = true
循环结束后 Finish[i] == false 的进程即死锁进程

易错点：死锁检测关注当前请求Request，而银行家算法关注最大需求Need；二者表格很像，但含义不同。

涉及知识点：2.1 线程、2.4 死锁检测

六、分页地址转换计算题 ⭐⭐⭐

题型特征

  • 给出逻辑地址、页面大小，求物理地址
  • 计算页表大小
  • 多级页表结构分析

核心公式

⭐ 逻辑地址 = 页号P × 页面大小 + 页内偏移W
⭐ 页号P = 逻辑地址 / 页面大小（整除）
⭐ 页内偏移W = 逻辑地址 % 页面大小（取余）
⭐ 物理地址 = 页框号F × 页面大小 + W

页面大小 = 2^n 时：
  页号 = 逻辑地址的高(32-n)位
  页内偏移 = 逻辑地址的低n位

页表大小计算

页表项数 = 进程地址空间大小 / 页面大小
页表大小 = 页表项数 × 每页表项字节数

典型真题

1. 页面大小4KB（2^12），页表如下。逻辑地址 0x00001234，求物理地址。

P = 0x1234 / 4096 = 1（页号1）
W = 0x1234 % 4096 = 0x0234（12位）
查页表得页框号F=5
物理地址 = 5 × 4096 + 0x234 = 0x5234

2. 32位地址，页大小4KB，每页表项4B。若采用两级页表，分别求出各级页表大小。

页面大小4KB=2^12，页内偏移12位
32-12=20位用于页号
每级页表10位（2^10=1024项）
一级页表：1024×4B=4KB（恰好一页）
二级页表：进程实际使用到的页面对应的二级页表
总页表大小取决于进程实际使用的地址范围

3. 逻辑地址32位，页大小4KB，每个页表项4B。求每进程最大页表大小。

页面数 = 2^32 / 2^12 = 2^20 = 1M页
页表大小 = 1M × 4B = 4MB

涉及知识点：3.1.3 基本分页存储管理

七、页面置换算法计算题 ⭐⭐⭐

题型特征

  • 给出页面访问序列和页框数，计算缺页次数和缺页率
  • 比较OPT、FIFO、LRU、CLOCK算法

核心概念

缺页次数 = 访问时页面不在内存的次数
缺页率 = 缺页次数 / 总访问次数

各算法计算要点

OPT：看将来，淘汰最远未来才用到或永不使用的页

FIFO：淘汰最早进入的页（注意Belady异常）

LRU：淘汰最久未被访问的页

CLOCK：循环扫描，访问位0的换出

典型真题

1. 访问序列：1,2,3,4,1,2,5,1,2,3,4,5。分配3个页框。求FIFO和LRU的缺页次数。

FIFO (3页框)：
前3次装入1、2、3；访问4换出1；访问1换出2；访问2换出3；访问5换出4；随后1、2命中；访问3换出1；访问4换出2；访问5命中。
缺页次数 = 9次
LRU (3页框)：
1缺, 2缺, 3缺, 4缺(换1), 1缺(换2), 2缺(换3), 5缺(换4), 1命中, 2命中, 3缺(换5), 4缺(换1), 5缺(换2)
缺页次数 = 10次

2. FIFO算法中Belady异常的含义是？举例说明。

Belady异常：增加页框数反而导致缺页次数增加
例：序列1,2,3,4,1,2,5,1,2,3,4,5
3页框：9次缺页；4页框：10次（反而增多！）

3. 改进型CLOCK算法，四类页面的淘汰优先级？

优先级(从高到低淘汰)：(0,0) → (0,1) → (1,0) → (1,1)
A=访问位, M=修改位

涉及知识点：3.2.3 页面置换算法

八、虚拟内存综合计算题

题型特征

  • 计算有效访问时间（EAT）
  • 快表（TLB）命中率对性能的影响

核心公式

⭐ EAT = (1-p) × 访存时间 + p × 缺页处理时间
⭐ 有TLB时：
   EAT = 命中率 × (TLB时间 + 访存时间) + (1-命中率) × (TLB时间 + 2×访存时间)

典型真题

1. 访存时间100ns，缺页处理时间25ms，缺页率0.01%。求EAT。

EAT = 0.9999 × 100ns + 0.0001 × 25000000ns
= 99.99ns + 2500ns ≈ 2600ns = 2.6μs

2. TLB命中率90%，TLB访问20ns，内存访问100ns。求EAT。

EAT = 0.9 × (20+100) + 0.1 × (20+100+100)
= 0.9 × 120 + 0.1 × 220
= 108 + 22 = 130ns

涉及知识点：3.2 虚拟内存管理

补充：动态分区分配题 ⭐⭐

题型特征

  • 给定空闲分区表和作业大小，判断首次适应/最佳适应/最坏适应的分配结果
  • 判断内存回收后如何合并空闲区
  • 辨析内部碎片和外部碎片

算法速查

算法选择规则常见结论
首次适应 FF从低地址开始找第一个足够大的分区速度快，低地址碎片多
邻近适应 NF从上次查找结束处继续找分布较均匀，可能破坏大分区
最佳适应 BF找满足要求的最小空闲分区容易产生最多小碎片
最坏适应 WF找最大的空闲分区保留小分区，破坏大分区

回收合并规则

  • 上邻空闲：与上邻合并，起始地址取上邻起始地址。
  • 下邻空闲：与下邻合并，起始地址不变。
  • 上下邻都空闲：三者合并为一个更大的空闲分区。
  • 上下邻都不空闲：新增一个空闲分区表项。

涉及知识点：3.1.2 连续分配管理方式

九、文件物理结构计算题 ⭐⭐

题型特征

  • 给定索引结构参数，计算最大文件大小
  • 连续/链接/索引分配的比较

Unix混合索引计算

⭐ 假设：块大小B，块号N位（每块号占N/8字节）
直接索引：10个直接块 → 10×B
一级间接：B/(N/8)个块 → B²/(N/8)
二级间接：(B/(N/8))²个块 → B³/(N/8)²
三级间接：(B/(N/8))³个块

最大文件大小 = (10 + 1级块数 + 2级块数² + 3级块数³) × B

典型真题

1. 块大小4KB，块号4B（32位）。Unix混合索引（10直接+1间接+1二级间接+1三级间接），最大文件多大？

每索引块可存块号数 = 4KB/4B = 1024个
直接：10 × 4KB = 40KB
一级间接：1024 × 4KB = 4MB
二级间接：1024² × 4KB = 4GB
三级间接：1024³ × 4KB = 4TB
总共 ≈ 4TB + 4GB + 4MB + 40KB ≈ 4TB

涉及知识点：4.1.3 文件的物理结构（索引分配）

补充：文件空闲空间管理题 ⭐⭐

题型特征

  • 计算位示图大小、块号对应的字号和位号
  • 比较空闲表法、空闲链表法、位示图法、成组链接法
  • 判断不同分配方式下适合的空闲空间管理方法

核心公式

位示图大小 = 磁盘块数 / 8 字节
字号 = 块号 / 每字位数
位号 = 块号 % 每字位数

方法对比

方法特点适用
空闲表法记录连续空闲区起始块号和块数连续分配
空闲链表法空闲块逐个链接分配单块方便，找连续块慢
位示图法一位表示一个磁盘块状态空间省，易找连续块
成组链接法空闲块分组保存，组间链接Unix常用

涉及知识点：4.2.3 文件系统实现

十、磁盘调度算法计算题 ⭐⭐

题型特征

  • 给出磁头当前位置和请求序列，计算平均寻道长度
  • 比较FCFS、SSTF、SCAN、C-SCAN

计算方式

平均寻道长度 = 总移动磁道数 / 请求次数

各算法移动方向

SCAN（电梯算法）：当前方向一直走到底，反向

C-SCAN：单向到底，快速回起点，不回服务

LOOK：不到端点就反向（实际系统使用）

C-LOOK：LOOK的单向+快速回起点版

典型真题

1. 磁头在100，请求序列：55,58,39,18,90,160,150,38,184。求SSTF和SCAN（向磁道号增大方向）的平均寻道长度。

SSTF（每次选最近的）：
100→90(10)→58(32)→55(3)→39(16)→38(1)→18(20)→150(132)→160(10)→184(24)
总移动 = 10+32+3+16+1+20+132+10+24 = 248
平均 = 248/9 ≈ 27.6
SCAN（向增加方向）：
100→150(50)→160(10)→184(24)→90(94)→58(32)→55(3)→39(16)→38(1)→18(20)
总移动 = 50+10+24+94+32+3+16+1+20 = 250
平均 = 250/9 ≈ 27.8

涉及知识点：5.3.1 磁盘调度算法

十一、磁盘访问时间计算题

题型特征

  • 给出磁盘参数（转速、寻道时间等），计算读一块数据的时间

核心公式

⭐ 总访问时间 Ta = 寻道时间 Ts + 旋转延迟 Tr + 传输时间 Tt

旋转延迟 Tr = 1/(2×转速)  [平均转半圈]
  例：7200RPM → 1/(2×120rps) = 4.17ms

传输时间 Tt = 数据量 / 传输速率
  传输速率 = 转速 × 每磁道字节数

典型真题

1. 磁盘7200RPM，平均寻道8ms，每磁道1MB，读4KB数据，求总时间。

Tr = 60/(2×7200) = 4.17ms
传输速率 = 7200/60 × 1MB = 120MB/s
Tt = 4KB / 120MB/s = 0.033ms
Ta = 8 + 4.17 + 0.033 ≈ 12.2ms

涉及知识点：5.3 磁盘和固态硬盘

十二、文件目录与链接综合题

题型特征

  • 文件共享方式比较
  • 硬链接与软链接的场景分析

核心辨析

场景用硬链接用软链接
跨文件系统共享❌✅
原文件删除后仍可用✅❌
需要不同权限❌(同inode)✅

典型真题

1. 文件A的inode号为100，创建硬链接B指向A。再删除A后，B还能访问吗？

能。硬链接B与A共享inode 100，删除A只减少引用计数
只要引用计数>0，文件数据不释放，B仍可访问

2. 创建软链接C指向A，删除A后C还能用吗？

不能。C存的是A的路径名，A被删除后C变成悬空链接

涉及知识点：4.2.2 硬链接和软链接

十三、I/O控制方式演变题

题型特征

  • 选择/比较四种I/O控制方式
  • 计算不同方式下CPU占用时间

四种方式对比

方式CPU干预传送适用
程序查询全程字/字节简单低速
中断驱动每单位中断字/字节低速设备
DMA开始+结束块高速块设备
通道极少多块大型机

典型真题

1. 从磁盘读1KB数据，轮询方式每次读1B需1μs CPU处理，中断方式每次中断需10μs处理，DMA方式设置需100μs。比较CPU开销。

轮询：1KB×1μs = 1024μs
中断：中断次数取决于设备，假设每字节中断→1024×10μs = 10240μs
DMA：仅100μs → DMA开销最小

涉及知识点：5.1.2 I/O控制方式

十四、SPOOLing与缓冲区计算题

题型特征

  • 理解SPOOLing如何将独占设备改造为共享设备
  • 计算单缓冲/双缓冲的处理时间

核心公式

单缓冲：T = max(C, T) + M
双缓冲：T = max(C, T) ← CPU和设备完全并行

C = CPU处理一块的时间
T = 设备输入一块的时间
M = 缓冲区→用户区传送时间

典型真题

1. 某进程处理数据块，CPU处理时间100μs，设备输入时间200μs，M=0。分别求无缓冲、单缓冲、双缓冲的平均处理时间。

无缓冲：串行，每块300μs
单缓冲：max(100,200)+0 = 200μs/块
双缓冲：max(100,200) = 200μs/块
注：M=0时单缓冲和双缓冲结果相同。若M>0，单缓冲需加M

2. SPOOLing系统由哪几部分组成？

输入井和输出井（磁盘空间）、输入进程和输出进程、井管理程序
核心思想：用磁盘缓存模拟独占设备

涉及知识点：5.2.1 缓冲区管理、5.2 设备独立性软件（SPOOLing）

十五、操作系统引导过程题

题型特征

  • OS引导的完整步骤排序
  • MBR、引导扇区相关计算

引导步骤

ROM BIOS → MBR(0扇区) → PBR(活动分区) → Boot Loader → OS内核

典型真题

1. 操作系统引导的正确顺序是？

2. MBR占多少个扇区？包含哪些内容？

1个扇区（512B）
主引导程序446B + 分区表64B + 结束标志55AA 2B
