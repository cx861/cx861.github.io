一、计算机网络性能指标与时延计算题

题型特征

  • 选择题：给定场景，计算总时延、发送时延、传播时延
  • 综合分析：结合分组交换/电路交换，比较时延
  • 408统考几乎每年必考

核心解法

1. 总时延计算

总时延 = 发送时延 + 传播时延 + 处理时延 + 排队时延
发送时延 = 数据帧长度(bit) / 发送速率(bit/s)
传播时延 = 信道长度(m) / 传播速率(m/s)

2. 分组交换流水线计算 ⭐

总时间 = 第一个分组到达时间 + (m-1)×每段发送时延
或：总时间 = (m + k - 1) × T

其中：m = 报文大小 / 每分组数据大小
     k = 链路段数
     T = 每段链路的发送时延(最大发送时延)

3. 电路交换 vs 分组交换

电路交换总时间 = 连接建立时延 + 报文大小/带宽 + 连接释放时延
分组交换总时间 = 第一个分组到达时间 + 后续分组流水发送时间

典型真题

1. [2010统考] 主机A和B之间链路带宽100Mb/s，传播时延5ms。A向B发送1500B分组，B立即回复64B确认帧。求A从发送到收到确认的总时间。

解：发送时延 = 1500×8/100M = 0.12ms；确认发送时延 = 64×8/100M = 0.00512ms
总时间 = 0.12 + 5 + 0.00512 + 5 = 10.125ms

2. [2013统考] 分组交换网络，H1→H2经过两段链路。带宽100Mb/s，时延带宽积1000b。发送1MB文件，分组1000B。求最少时间。

解：m = 1MB/1000B = 1000组，k = 2段
每段发送时延 T = 1000×8/100M = 0.08ms
时延带宽积 = 传播时延×带宽 = 1000b → 传播时延 = 1000/100M = 0.01ms
总时间 = (m+k-1)T + 2×传播时延 = (1000+1)×0.08 + 2×0.01 = 80.10ms

3. [2023统考] 2段链路带宽100Mb/s，时延带宽积1000b，H1向H2发1MB文件，分组1000B。

解：分组数 m = 1MB/1000B = 1000, k=2, T=80μs
总时延 = (m+k-1)T = 1001×80μs = 80.08ms
两段链路的传播时延 = 1000b/100Mb/s×2 = 0.02ms
总时间 ≈ 80.10ms（若无其他时延则为 80.08ms）

涉及知识点：1.1.6 计算机网络的性能指标、1.1.4 电路交换/报文交换/分组交换

二、奈奎斯特与香农定理计算题

题型特征

  • 给出信道带宽、信号状态数或信噪比，求最大数据传输速率
  • 综合题：同时给出无噪声和有噪声条件，需取最小值
  • 选择题高频出现

核心公式

⭐ 奈奎斯特定理（无噪声）：最大速率 = 2W × log₂V
⭐ 香农定理（有噪声）：最大速率 = W × log₂(1 + S/N)
   分贝转换：S/N(dB) = 10 × log₁₀(S/N)
   例：30dB → S/N = 1000

实际最大速率 = min(奈氏极限, 香农极限)

解题步骤

  1. 仅知带宽W和状态数V → 用奈奎斯特：2W × log₂V
  2. 仅知带宽W和信噪比S/N → 用香农：W × log₂(1+S/N)
  3. 两者都给出 → 分别计算，取较小值
  4. 注意单位：带宽Hz，速率bit/s；码元速率(Baud)与比特率不同

典型真题

1. 信道带宽4kHz，信噪比30dB，求最大数据传输速率。

S/N(dB)=30 → S/N=1000
香农：C = 4000 × log₂(1+1000) ≈ 4000 × 10 = 40kb/s

2. 带宽3kHz，无噪声，采用QAM-64调制（V=64），求最大速率。

奈氏：C = 2 × 3000 × log₂64 = 6000 × 6 = 36kb/s

3. 带宽4000Hz，信噪比127，二进制信号。求最大速率。

香农：C = 4000 × log₂(1+127) = 4000 × 7 = 28000b/s
奈氏（V=2）：C = 2 × 4000 × log₂2 = 8000b/s
取 min(28000, 8000) = 8000b/s

4. 带宽20MHz，信噪比1001。先求原极限，再带宽翻倍、信噪比到10001后求提升倍数。

原：香农=20M×log₂1002≈200Mb/s，奈氏若32QAM=2×20M×5=200Mb/s，极限200Mb/s
新：香农=40M×log₂10002≈520Mb/s，奈氏=2×40M×5=400Mb/s，极限400Mb/s
提升：400/200 = 2倍

涉及知识点：2.1.2 信道的极限容量

三、编码与调制波形识别题

题型特征

  • 给出波形图，判断编码方式
  • 给出编码方式，画出波形
  • 计算码元速率、比特率关系

核心知识

编码方式判断特征
NRZ无跳变，高=1低=0
曼彻斯特每个码元中间必定跳变，高→低=1/低→高=0
差分曼彻斯特码元中间跳变；码元开始处有跳变=0，无跳变=1
NRZI电平反转=0，不变=1

⚠️ 关键区分：

  • 曼彻斯特看码元中间跳变方向
  • 差分曼彻斯特看码元开始处有无跳变（中间必定跳变用于同步）

计算公式

比特率(bit/s) = 波特率(Baud) × log₂V
其中 V = 信号可取的离散值个数

QAM：V = 振幅数 × 相位数
每个码元携带比特数 = log₂V

典型真题

1. 4个相位，每个相位4种幅度QAM，带宽3kHz。求最大速率。

V = 4×4 = 16，log₂16 = 4
奈氏：2 × 3000 × 4 = 24kb/s

2. 给出曼彻斯特编码波形，求对应比特串。

高→低表示1，低→高表示0：观察跳变方向
答案可能为 00110110 或 11001001（取决于约定）

3. 16种变化状态的信号，采样率8Hz。求最大数据传输速率。

每个信号携带 log₂16 = 4 比特
最大速率 = 8 × 4 = 32b/s

涉及知识点：2.1.3 编码与调制

四、CRC循环冗余码计算题

题型特征

  • 给出待发送数据和生成多项式，求CRC检验码
  • 给出接收数据，判断是否有差错

解题步骤

1. 将生成多项式转为二进制：G(x)=x³+x+1 → 1011
   生成多项式阶数 r = 最高次数

2. 在数据尾部添加 r 个 0

3. 用模2除法（异或）除以生成多项式对应二进制

4. 得到的 r 位余数即为CRC检验码

5. 将余数替换步骤2中添加的 0

6. 验证：接收方用同一G(x)除接收数据，余数为0则无误

模2除法规则

  • 被除数最高位为1：商1，除数与被除数异或
  • 被除数最高位为0：商0，除数用0（即无操作）
  • 最终余数位数 < 除数位数

典型真题

1. 待发送数据101001，G(x)=x³+x²+1（即1101）。求CRC码。

r=3，数据尾部加3个0：101001000
101001000 ÷ 1101 （模2除法）
余数 = 001，发送数据 = 101001001

涉及知识点：3.3.1 循环冗余码(CRC)

五、ARQ协议窗口与信道利用率

题型特征

  • 计算发送窗口、信道利用率
  • 比较停止-等待、GBN、SR的效率
  • 选择题/计算题均有

核心公式

⭐ 信道利用率 U = (WT × 发送时延) / (发送时延 + 2×传播时延)
                = (WT × 发送时延) / RTT_effective

⭐ 最大吞吐量 = U × 带宽 = WT / RTT × 每帧大小

GBN窗口最大 = 2^n - 1（n为序号比特数）
SR窗口最大 = 2^(n-1)

解题要点

停止-等待：WT=1，利用率很低

GBN：WT > 1，WR=1，累积确认

SR：WT = WR，各自缓冲

Pipelining计算：

  • 首帧发送后，在收到ACK前可连续发 WT 帧
  • 若 WT×发送时延 ≥ RTT → 信道利用率可达100%

典型真题

1. 帧长1000B，带宽1Mb/s，传播时延270ms，双向确认。求停止-等待协议的信道利用率。

发送时延 = 1000×8/1M = 8ms
RTT_effective = 8 + 270×2 = 548ms（忽略确认帧发送时延）
U = 8/548 ≈ 1.46%

2. 同上题，为使利用率达到50%，发送窗口应为多少？

WT × 8 / (8+540) ≥ 0.5 → WT ≥ 34.25 → 至少35帧

3. 序号3比特（0~7），分别求GBN和SR的最大发送窗口。

GBN：WT_max = 2³ - 1 = 7
SR：WT_max = 2^(3-1) = 4

涉及知识点：3.4 流量控制与可靠传输机制

六、CSMA/CD冲突检测计算题

题型特征

  • 给定网络参数，计算争用期、最短帧长
  • 判断冲突是否发生

核心公式

⭐ 争用期（冲突窗口）= 2τ（τ=端到端传播时延）
⭐ 最短帧长 = 数据传输速率 × 争用期

截断二进制指数退避：
    第k次重传（k≤10），退避时间 = r × 争用期
    r ∈ {0, 1, 2, ..., min(2^k-1, 1023)}
    最大重传16次

解题要点

  1. 发送帧长 < 最短帧长 → 冲突无法检测（帧已发完）
  2. 冲突发生时间 ≤ τ（第一比特到达前）
  3. 检测到冲突后，发送方发送人为干扰信号（Jam）

典型真题

1. 1km电缆，数据传输速率1Gb/s，传播速率200m/μs。求最短帧长。

τ = 1000/200 = 5μs，争用期 = 2τ = 10μs
最短帧长 = 1Gb/s × 10μs = 10000bit = 1250B

2. 以太网速率10Mb/s，争用期51.2μs。站A和B同时发送，A在第5次重传时发送成功。

A前4次失败，第5次成功
第5次退避：k=5，r ∈ {0,...,31}，随机选取
若A选r最小而B冲突，A成功

涉及知识点：3.5.2 随机访问介质访问控制（CSMA/CD）

补充、交换机自学习、VLAN与广播域题

题型特征

  • 给出交换机初始转发表和若干帧，判断学习、转发、泛洪或丢弃
  • 给出网络拓扑，计算冲突域和广播域数量
  • 考查Access/Trunk端口、802.1Q标签和VLAN间通信方式

核心解法

交换机处理帧：
1. 先学习源MAC：源MAC → 入端口
2. 再查目的MAC：
   查不到：除入端口外泛洪
   查到且出端口不同：转发
   查到且出端口相同：丢弃

冲突域/广播域：
Hub：不隔离冲突域，不隔离广播域
交换机：每个端口一个冲突域，默认不隔离广播域
路由器：隔离广播域，也隔离冲突域
VLAN：逻辑隔离广播域

典型题

1. 交换机空表，A在1口向B发送帧，B在2口。交换机如何处理？

先学习 A→1口；由于不知道B在哪个端口，向除1口外所有端口泛洪。B响应后，交换机再学习 B→2口。

2. 一台24口交换机划分3个VLAN，每个VLAN有8台主机。共有多少广播域？

每个VLAN是一个广播域，因此共有 3个广播域。交换机端口一般各自形成冲突域，因此最多可看作24个冲突域。

3. 两台交换机之间需要承载VLAN 10和VLAN 20，应使用什么端口？

使用Trunk端口，通过802.1Q标签区分不同VLAN；接终端主机通常使用Access端口。

涉及知识点：3.6.4 VLAN、3.8.2 以太网交换机

七、IP分片计算题 ⭐⭐⭐

题型特征（408热门考点）

  • 给出原始IP数据报大小、MTU，求分片后的片偏移、MF标志、总长度
  • 给出若干分片信息，求原始数据报大小

核心规则

⚠️ 片偏移以 8 字节为单位！
⚠️ 除最后一片外，每片数据部分长度必须是 8 字节的整数倍！

片偏移 = 该片数据第一个字节在原始数据中的位置 / 8
每片最大数据长度 = MTU - 首部长度（且为8的倍数）
每片总长度 = 首部长度 + 片数据长度
MF标志：最后一片=0，其他片=1

解题步骤

  1. 计算可用的数据部分长度：MTU - 首部长度（通常20B）
  2. 取小于等于且能被8整除的最大值（如 1480B = 185×8）
  3. 计算分片数：⌈总数据/每片数据⌉
  4. 计算每片的片偏移：(片号-1)×每片数据/8

典型真题

1. IP数据报总长4000B，首部20B，MTU=1500B。求各分片信息。

原始数据 = 4000-20 = 3980B
每片最大数据 = 1500-20 = 1480B（且为8倍数）

| 片号 | 总长度 | 片偏移 | MF | 数据量 |
|------|--------|--------|-----|--------|
| 1 | 1500 | 0 | 1 | 1480 |
| 2 | 1500 | 1480/8=185 | 1 | 1480 |
| 3 | 1060 | 2960/8=370 | 0 | 1020 |

2. 收到一个IP分片：MF=0，片偏移=800，数据长度200B。求原始数据报大小。

MF=0说明是最后一片
片偏移=800 → 该片数据起始字节 = 800×8 = 6400B
总数据量 = 6400 + 200 = 6600B
若首部20B，总长 = 6620B

涉及知识点：4.2.1 IPv4分组、4.2.2 IPv4地址

八、子网划分与CIDR计算题 ⭐⭐⭐

题型特征

  • 给定IP地址范围，划分子网
  • CIDR聚合/超网计算
  • 路由表最长前缀匹配
  • 网络地址、广播地址、可用IP范围计算

核心操作

⭐ 网络地址 = IP地址 & 子网掩码
⭐ 广播地址 = 网络地址 | (~子网掩码)（低32位部分取反）
⭐ 可用IP范围 = 网络地址+1 ~ 广播地址-1
⭐ 子网数 = 2^n（n为借位比特数）
⭐ 每子网主机数 = 2^(32-前缀长度) - 2

CIDR路由聚合

取各网络号的共同前缀位：
例：192.168.1.0/24 和 192.168.2.0/24
    → 192.168.0.0/22（取前22位相同部分）

解题步骤

子网划分：

  1. 确定需要多少子网（或每子网需要多少主机），算出借位数
  2. 写出新的子网掩码
  3. 计算每子网的网络地址和可用范围

路由聚合：

  1. 写出二进制形式
  2. 找共同前缀
  3. 取共同部分作为聚合后地址，前缀长度为共同位数

典型真题

1. IP：192.168.1.10/26，求网络地址、广播地址、可用IP数。

子网掩码：255.255.255.192
网络地址 = 192.168.1.10 & 255.255.255.192 = 192.168.1.0
广播地址 = 192.168.1.0 + (64-1) = 192.168.1.63
可用IP = 64 - 2 = 62个（192.168.1.1 ~ 192.168.1.62）

2. 路由表中有 172.16.0.0/18 和 172.16.64.0/18，能否聚合？

172.16.0.0/18：172.16.00|000000.0
172.16.64.0/18：172.16.01|000000.0
前17位相同，聚合为 172.16.0.0/17

3. 最长前缀匹配：目的IP 192.168.1.5，路由表有 192.168.0.0/20 和 192.168.1.0/24，走哪条？

192.168.1.5 & /20 → 192.168.0.0，匹配
192.168.1.5 & /24 → 192.168.1.0，匹配
选前缀最长的 /24 路由

涉及知识点：4.2.2 IPv4地址（分类、子网划分、CIDR）

九、ARP与分组转发综合题

题型特征

  • 给定网络拓扑，描述ARP的工作过程
  • 路由表查表转发过程

核心要点

⭐ ARP四种场景：

场景请求谁的MAC
同一网络，主机→主机目的主机的MAC
不同网络，主机→主机默认网关（路由器）的MAC
路由器→主机目的主机的MAC
路由器→路由器下一跳路由器的MAC

路由表转发：

  1. 提取目的IP
  2. 与路由表逐条匹配（目的IP & 子网掩码 == 网络地址？）
  3. 多条匹配→最长前缀匹配
  4. 无匹配→默认路由或丢弃

典型真题

1. 主机A(192.168.1.1/24)向主机B(10.0.0.1/8)发送数据，A的ARP请求是什么？

A和B不在同一网络，A需先将数据发给默认网关
ARP请求：默认网关的IP对应的MAC地址（非B的MAC）

2. 路由器收到目的IP=192.168.5.17的分组，路由表如下。走哪条？

192.168.0.0/16  → R1（匹配）
192.168.5.0/24  → R2（匹配）
0.0.0.0/0       → R3（默认，匹配）
三条都匹配，选前缀最长的：/24 → R2

涉及知识点：4.2.5 地址解析协议(ARP)、4.2.4 网络层转发分组的过程

十、路由协议比较题（RIP/OSPF/BGP）

题型特征

  • 选择题：比较三种路由协议的特点
  • 给出场景，选择合适的路由协议

快速对照表

维度RIPOSPFBGP
类型IGPIGPEGP
算法距离向量(DV)链路状态(LS)路径向量(PV)
度量跳数（≤15）代价（带宽相关）路径属性/策略
协议层次应用层网络层应用层
传输/封装UDP 520端口IP协议号89TCP 179端口
更新方式周期性（30s）广播全部路由触发更新，洪泛LSA增量更新
收敛速度慢快慢
适用范围小型网络中大型网络AS之间（全球）
环路防护水平分割、毒性反转天然无环路（SPF算法）路径向量防环

典型真题

1. 以下哪个协议使用UDP传输？

RIP（UDP 520）；OSPF直接封装在IP中；BGP使用TCP

2. 关于OSPF的说法，正确的是？

OSPF是链路状态协议，使用Dijkstra算法，收敛快
OSPF支持区域划分，区域0为骨干区域
OSPF报文直接封装在IP数据报中（协议号89）

3. 最大跳数限制是由哪个协议引入的？

RIP（最大15跳，16=不可达）

涉及知识点：4.4 路由算法与路由协议

补充、NAT/DHCP/ICMP综合题

题型特征

  • 给出内网主机访问公网的过程，判断NAT表项和地址/端口变化
  • 考查DHCP四步交互、源/目的IP和UDP端口
  • 判断哪些情况发送或不发送ICMP差错报文

核心速记

专题必会点易错点
NAT/NAPT私有IP/端口 ↔ 公网IP/端口转换后需重算IP首部和TCP/UDP检验和
DHCPDORA：Discover、Offer、Request、ACK客户端端口68，服务器端口67；初始请求常用广播
ICMP封装在IP中，用于差错报告和询问ICMP差错报文出错、多播/广播、非首片分片不再发差错报告

典型题

1. 内网主机10.0.0.2:5000经NAT访问公网服务器1.1.1.1:80，NAT公网地址为202.1.1.1。NAT表可能是什么？

可建立映射：10.0.0.2:5000 ↔ 202.1.1.1:某公网端口。外出报文源地址/端口被替换，返回报文再按NAT表还原。

2. DHCP客户机刚启动时还没有IP地址，Discover报文常见源/目的IP是什么？

源IP常为 0.0.0.0，目的IP为 255.255.255.255；UDP源端口68，目的端口67。

3. IP分片的第二片在传输中出错，路由器是否发送ICMP差错报告？

不发送。对第一个分片以外的后续分片，不发送ICMP差错报告。

涉及知识点：4.2.3 NAT、4.2.6 DHCP、4.2.7 ICMP

十一、TCP三次握手与四次挥手 ⭐⭐⭐

题型特征

  • 选择题：判断TCP连接/释放过程中各报文段的标志位和序号
  • 计算SYN、ACK、seq、ack的值

三次握手过程

客户                           服务器
  |------SYN, seq=x------------>|  (SYN-SENT → LISTEN)
  |                              |  (SYN-RCVD)
  |<-----SYN+ACK, seq=y, ack=x+1| 
  |                              |
  |------ACK, seq=x+1, ack=y+1->|  (ESTABLISHED)
  |                              |  (ESTABLISHED)

四次挥手过程

客户                           服务器
  |------FIN, seq=u------------>|  (FIN-WAIT-1)
  |<-----ACK, seq=v, ack=u+1----|  (CLOSE-WAIT)
  |  (FIN-WAIT-2)                |
  |<-----FIN, seq=w, ack=u+1----|  (LAST-ACK)
  |------ACK, seq=u+1, ack=w+1->|  (TIME-WAIT)
  |  (等待2MSL后CLOSED)          |  (CLOSED)

⚠️ 易错点

  1. SYN和FIN各消耗一个序号（即使不含数据也占序号）
  2. 连接建立时的第三次握手ACK不消耗序号（若不带数据）
  3. TIME-WAIT = 2MSL（最长报文段寿命），约为2分钟
  4. 为什么握手三次、挥手四次？
    • 握手：服务器SYN和ACK可合并（第二次）
    • 挥手：服务器收到FIN后可能还有数据要发，ACK和FIN需分开发

典型真题

1. 主机A向B发送连接请求，SYN=1，seq=100。B同意连接，应回复什么？

SYN=1，ACK=1，seq=y（任意初始值），ack=101（100+1）

2. TIME-WAIT状态的作用？

① 确保最后一个ACK能到达服务器（若丢失服务器可重发FIN）
② 让旧连接的所有报文在网络中消失

涉及知识点：5.3.3 TCP连接管理

十二、TCP拥塞控制计算题 ⭐⭐⭐

题型特征

  • 给出cwnd变化曲线图，分析拥塞控制行为
  • 计算各时间点cwnd、ssthresh的值
  • 判断何时发生超时、何时发生3个重复ACK

核心行为

事件cwnd变化ssthresh变化后续阶段
初始1初始值（通常16等）慢开始
慢开始中（每RTT）×2不变慢开始
cwnd≥ssthresh线性+1/RTT不变拥塞避免
超时→1=cwnd/2慢开始
3个重复ACK=ssthresh=cwnd/2=cwnd/2快恢复→拥塞避免

⚠️ 关键区分

  • 超时：cwnd骤降为1，ssthresh=cwnd/2
  • 3个重复ACK：cwnd只降为一半（ssthresh值），更温和

解题步骤

分析cwnd曲线图时：

  1. 看增长模式：指数=慢开始，线性=拥塞避免
  2. 看骤降点：降为1=超时；降为一半=3个重复ACK
  3. 标记每次事件后的ssthresh值

典型真题

1. cwnd从1开始指数增长到16后线性增长到24，然后骤降为1。发生了什么？

指数增长→慢开始（ssthresh至少16）
线性增长→拥塞避免
cwnd=24时骤降到1→发生超时
新的 ssthresh = 24/2 = 12
之后从1重新慢开始

2. cwnd=16，收到3个重复ACK后，cwnd和ssthresh为多少？

ssthresh = cwnd/2 = 8
cwnd = ssthresh = 8（快恢复）
之后线性增长（拥塞避免）

涉及知识点：5.3.6 TCP拥塞控制

十三、TCP序号与确认号计算题

题型特征

  • 给定TCP连接的初始序号和已传输数据量，计算当前seq和ack

计算规则

⭐ seq = 本报文段数据第一个字节的序号
⭐ ack = 对方初始序号 + 已收到对方数据字节数 + 1（若SYN/FIN）
⭐ SYN和FIN各消耗一个序号
⭐ 纯ACK报文（无数据）不消耗序号

典型真题

1. 主机A发起连接：SYN=1，seq=100。建立连接后A发送200B数据。求B回复的确认号。

连接建立消耗1个序号（SYN），seq从101开始
A发送200B，占用seq 101~300
B确认号 = 301（期望下一个字节）

2. A的seq=100，向B发送300B。B的seq=200，向A发送200B并捎带确认。求B报文的seq和ack。

B的seq = 200（B自己的初始序号，假设未发过数据）
B的ack = 100 + 300 = 400（确认收到A的300B）
若B还发送了200B数据，则下次A的ack = 200 + 200 = 400

涉及知识点：5.3.2 TCP报文段、5.3.3 TCP连接管理

补充、UDP校验和与TCP流量控制题

题型特征

  • 判断UDP/TCP检验和覆盖范围，与IP首部检验和区别
  • 给出接收窗口rwnd、拥塞窗口cwnd，求实际发送窗口
  • 考查零窗口、持续计时器、零窗口探测报文和糊涂窗口综合征

核心规则

UDP检验和覆盖：伪首部 + UDP首部 + 数据
TCP检验和覆盖：伪首部 + TCP首部 + 数据
IP首部检验和：只检验IP首部

TCP实际发送窗口 = min(rwnd, cwnd)
rwnd用于流量控制：保护接收方
cwnd用于拥塞控制：保护网络

典型题

1. UDP检验和计算时，伪首部是否会被发送？

不会。伪首部只参与检验和计算，用来把源/目的IP、协议号、UDP长度纳入差错检测。

2. rwnd=12KB，cwnd=8KB，发送方最多还能发送多少未确认数据？

发送窗口取两者较小值：min(12KB, 8KB)=8KB。

3. 接收方通告零窗口后，窗口更新报文丢失怎么办？

发送方启动持续计时器，超时后发送零窗口探测报文，避免双方永久等待。

涉及知识点：5.2.2 UDP检验和、5.3.5 TCP流量控制

十四、DNS查询过程题

题型特征

  • 描述DNS域名解析的完整过程
  • 区分递归查询和迭代查询
  • 知道各级域名服务器的作用

DNS解析流程

主机                    本地DNS         根DNS         com DNS       example.com DNS
 |--www.example.com?---->|
 |                       |--www.example.com?----->|
 |                       |<----com DNS地址---------|
 |                       |
 |                       |--www.example.com?---------------.->|
 |                       |<----example.com DNS地址-----------|
 |                       |
 |                       |--www.example.com?----------------------->|
 |                       |<----1.2.3.4------------------------------|
 |<-----1.2.3.4----------|
主机→本地DNS：递归查询
本地DNS→各级服务器：迭代查询

典型真题

1. 用户在浏览器输入www.example.com，简述DNS解析过程。

① 浏览器查本地DNS缓存
② 查hosts文件
③ 向本地域名服务器递归查询
④ 本地DNS向根DNS迭代查询→得.com DNS地址
⑤ 向.com DNS查询→得example.com DNS地址
⑥ 向example.com DNS查询→得IP地址
⑦ 返回IP给浏览器

2. DNS使用什么传输层协议？

一般使用UDP 53端口
当响应超过512字节或区域传送时使用TCP 53端口

十五、FTP双连接理解题

题型特征

  • 区分FTP的控制连接和数据连接
  • 端口号辨析

核心知识

⭐ FTP使用两条TCP连接：
    控制连接：服务器21端口，传输命令，保持整个会话
    数据连接：服务器20端口(PORT)或协商端口(PASV)，每次传输数据时建立
模式数据连接建立方式
主动PORT服务器从20端口主动连接客户端
被动PASV客户端连接服务器协商的随机端口

典型真题

1. FTP传输文件时，控制连接使用的端口是？

服务器21端口（控制连接始终是21）

2. 为什么FTP需要两条连接？

控制连接用于传输命令（维持会话状态），数据连接用于传输文件数据
分离控制与数据，允许在传输数据同时发送控制命令（如中断传输）

涉及知识点：6.3 文件传输协议(FTP)

十六、HTTP综合题

题型特征

  • HTTP请求/响应报文格式
  • 持久连接与非持久连接的时间计算
  • 状态码辨析

核心知识

HTTP请求报文格式：

GET /index.html HTTP/1.1          ← 请求行
Host: www.example.com              ← 首部行
Connection: keep-alive
                                    ← 空行
                                    ← 实体（可选）

关键状态码：

码含义
200OK
301永久重定向
302临时重定向
304未修改（使用缓存）
404未找到
500服务器内部错误

持久连接与非持久连接：

非持久HTTP/1.0：每个对象需要一个TCP连接
  RTT开销 = 2RTT × 对象数
  
持久HTTP/1.1：一个TCP连接传输多个对象
  RTT开销 = 2RTT（建立连接）+ 对象传输时间

典型真题

1. 一个HTML页面包含8个小图片。HTTP/1.0非持久连接需要多少次RTT？

HTML页面：2RTT（建立+请求）
8个图片：各需2RTT = 16RTT
总计：18RTT（串行）/ 部分可并行

2. HTTP/1.1持久连接（非流水线）获取同上页面需要多少RTT？

TCP连接：1RTT（三次握手前1.5RTT）
HTML：1RTT
8图片：各1RTT（非流水线需等前一个返回）= 8RTT
总计：约10.5RTT

3. HTTP响应状态码404表示什么？

Not Found - 请求的资源未找到

涉及知识点：6.5.2 超文本传输协议(HTTP)

补充、电子邮件协议辨析题

题型特征

  • 区分SMTP、POP3、IMAP、MIME的作用和端口
  • 给出邮件收发过程，判断哪一段使用哪个协议
  • 考查“推/拉协议”、邮件服务器和用户代理的职责

核心对照

协议/扩展作用传输层/端口关键词
SMTP发送邮件、服务器间转发TCP 25推协议、命令/响应
POP3从服务器下载邮件TCP 110拉协议、离线阅读
IMAP在线管理服务器邮件TCP 143拉协议、多终端同步
MIME扩展邮件内容格式-支持中文、图片、附件等非ASCII内容

典型题

1. 用户A把邮件发到自己的邮件服务器，再转发到用户B的邮件服务器，使用什么协议？

两段通常都使用SMTP。

2. 用户B从邮件服务器读取邮件，可使用哪些协议？

可使用POP3或IMAP。POP3偏下载，IMAP偏服务器端管理与多终端同步。

3. SMTP只能直接传7位ASCII文本，如何发送图片附件？

使用MIME扩展，对非ASCII内容和附件进行描述与编码。

涉及知识点：6.4 电子邮件

十七、综合应用题（跨章节）

题型特征

  • 综合多章知识点的大型场景题
  • 需要计算+分析+描述

常见综合场景

场景1：文件传输全过程分析

涉及：DNS解析 → TCP连接建立 → HTTP请求 → IP路由转发 → 数据链路层封装

场景2：网络拓扑分析与故障排查

涉及：IP地址规划、子网划分、路由表配置、ARP过程、交换机工作原理

典型提问点：

  • 主机间能否通信？（检查IP地址是否在同一子网）

解题要点

  1. 数据在各层的封装：
   应用层：HTTP报文
   传输层：TCP报文段（端口号）
   网络层：IP数据报（IP地址）
   数据链路层：帧（MAC地址）
   物理层：比特流
